# N112.0 — pinning the native self-host `assemble_sel` crash (diagnosis, 0.3.1)

Status: **DIAGNOSTIC (N112.0, 2026-08-06).** Base `fix/retirement`. This is the load-bearing gate the
design (`docs/design/native-slice-str-rep-separation-0.3.1.md` §2, §7) pre-registers: reproduce the
native fixpoint crash, pin its EXACT mechanism, and answer — falsifiably — whether the #112 rep flip
(`[]T` 2-word → 3-word) will fix it. It does **NOT** change any representation.

## Verdict (read this first)

**The crash is a REGION-LIFETIME / by-address-element ESCAPE bug — category (d), an INDEPENDENT bug,
NOT the fat-WIDTH (16-vs-24) / stride / rep mismatch the design's leading hypothesis (a)/(b)
proposed.** The #112 rep separation (`str` stays 2-word, `[]T` becomes 3-word) will **NOT** fix this
crash. Proof and evidence below.

## How it was reproduced (under the 2.5 GiB cap)

The released seed's own native backend predates the aggregate-push (`tk_slice_elem_box`) lowering, so
it honest-stops rather than reproducing. The reproduction path is therefore:

1. `TEKO_BACKEND=c` seed → **gen0** (this tree's compiler, C-built). Peak RSS **1512.7 MB** (< 2.5 GiB).
2. gen0 `TEKO_BACKEND=native` builds the reproducing probe (below); running it SIGSEGVs (exit 139),
   deterministically under `setarch -R` (ASLR off).

A minimal reproducing probe lives at `examples/probes/n112_assemble_sel_crash/` — C route exit **42**,
native/own backend exit **139 (SIGSEGV)**. It is the pre-registered gate: it must reach exit 42 once
the crash is fixed.

## The reduced shape, and the bisection that pinned it

`src/build/assemble.tks::assemble_sel` pushes `parser::Item = { content: ItemKind; namespace: str;
file: str }` into a `[]parser::Item` in a loop. `ItemKind` is a variant with SEVERAL aggregate cases
(`Function`, `TypeDecl`, …) whose payloads carry fat-element slices (`[]Stmt`, `[][]…`). The probe is
that shape reduced. A single-variable bisection (each build+run ~0.5 s) isolated the trigger:

| shape of the pushed aggregate's variant payload | # aggregate cases | trailing `str` fields on the outer aggregate | result |
|---|---|---|---|
| `xs: []i64` (scalar slice) + `str` | 1 | yes | **pass** |
| `params: []Param` (slice of struct, by-address elems) | 2 | yes | **pass** |
| `body: [][]i64` (fat-element slice) | 1 (`Func | i64`) | yes | **pass** |
| `body: [][]i64` (fat-element slice) | 2 (`Func | TypeDecl | i64`) | yes | **CRASH** |
| `body: []str` (fat-element slice) | 2 | yes | **CRASH** |
| `body: []i64` (scalar-element slice) | 2 | yes | **pass** |
| `body: [][]i64`, outer aggregate = `{ content }` only | 2 | **no** | **pass** |

**The trigger is the intersection of THREE conditions:** (1) a variant with **2+ aggregate cases**,
(2) a case payload holding a **fat-ELEMENT slice** (`[]str` / `[][]T` — element stride
`fat_slot_bytes()` = 16, i.e. the elements are themselves `{ptr,len}` fats), and (3) **trailing fields
AFTER the variant** on the enclosing aggregate (the read-back victims). Remove any one and it passes.

## The exact fault (gdb, ASLR off, deterministic)

```
tk_mem_copy(dst=<stack `it`>, src=0x5, n=40)   →   __memcpy_avx512… SIGSEGV
  #1 tk_mem_copy            (src/runtime/teko_rt.c)
  #2 __teko_native_vmain    (the read-back `let it = one[j]` aggregate copy; n = sizeof(Item) = 40)
```

`one[j]` yielded a **garbage element address `0x5`**. Tracing `tk_slice_elem_box` / `tk_slice_push` /
`tk_mem_copy` across construction shows every width is CORRECT — array box 16/32, case-struct box 32,
variant wrapper box 24, `Item` box 40, by-address element pointer push esz 8. **No 16-vs-24
disagreement anywhere.** The smoking gun is the boxed-element addresses REPEAT by parity: iteration 0
and iteration 2 both box their `Item` at the SAME address `0x…450` (iterations 1,3 share `0x…440`).
The per-iteration `tk_slice_elem_box` storage is being **reused/reclaimed**, so the `[]Item` buffer
holds aliasing then dangling element pointers; the next grow-realloc leaves `one[0] == 0x5`, and the
by-address copy faults.

This is precisely the class `src/lir/lower.tks:1620` (`open_native_region`) already documents as *"the
self-hosted `assemble_sel` gen2==gen3 crash"* — a pushed element's `tk_slice_elem_box` allocated in a
scoped region that the scope's own `tk_region_drop_u` frees while the slice still holds its address.
That doc's fix closes the **match-arm conveyance** instance (`bracket_depth > 0` skip). This probe
exhibits a **REMAINING** instance: a fat-element-slice payload in a multi-aggregate-case variant
pushed in a **plain loop** still lands the element box in a reclaimed region. The C route is immune —
it holds `[]struct` BY VALUE in the routed grow region, never boxing an element into the arm/loop
region.

## Corroboration at full scale (the real self-host)

gen0 `TEKO_BACKEND=native` building the WHOLE compiler:
- **under the 2.5 GiB cap:** SIGSEGV in `tk_region_alloc`, reached from `emit_native_x86` via
  `tk_slice_push_fo → tk_slice_push_r → tk_region_alloc` — a corrupt region pointer (the documented
  native-region-STATE-corruption family). The cap turns the corruption into an early mmap-failure
  fault (a memory-cap FINDING — see below).
- **uncapped:** `emit_native_x86` COMPLETES and emits `teko.o` (14.5 MB), but the object's relocations
  reference **garbage symbol names** (`ld.lld: error: undefined symbol: \xff\xff…`, `p\x9d`, `\t`) at
  `.text+0x27E83A…`, followed by `double free or corruption (out)` (SIGABRT). Garbage SYMBOL-NAME
  STRINGS in the emitted object is the same by-address / region string-data corruption the probe
  isolates, now clobbering the compiler's own symbol-name slices during native self-emit.

So the native fixpoint cannot even be REACHED locally: the native self-emit corrupts its own data
(`str`/slice buffers) before a byte-stable gen2 can exist.

## Why the #112 rep flip will NOT fix this crash (the falsification)

1. **Widths are already consistent.** Every box/push width the native backend computes for the
   crashing shape is correct at its expected value; there is no authority disagreeing at 16-vs-24. The
   fault is a dangling by-address element pointer (region reuse), not a mis-strided read/write.
2. **The `[]str` instance is rep-flip-IMMUNE by construction.** The probe reproduces the crash with a
   `[]str` payload, and `str` STAYS a 2-word `{ptr,len}` fat under #112 (str-no-widen is the owner's
   inviolable constraint, design §0). A width change that never touches `str` cannot cure a crash the
   `[]str` instance reproduces. `[][]T` reproduces it too, but `[]str` alone is a sufficient
   falsifier.
3. **Region lifetime is orthogonal to element width.** N112.3 changes how many bytes a slice VALUE
   occupies; it changes nothing about which region the pushed aggregate's element box is allocated in,
   nor when that region is dropped.

The rep separation remains architecturally worthwhile for its OTHER goals (native `grow_inplace` /
F3-native / De-C, design §6) — but its crash-fix claim (design §2 N112.3, "This crumb fixes the
crash") is **re-scoped by this diagnosis**: the native fixpoint crash needs a REGION-ASSIGNMENT fix
(the by-address element box of a loop/arm push must be conveyed to the escaping slice's region, not the
scope's own reclaimed region — extend the `open_native_region` conveyance skip to the plain-loop
fat-element-payload push), independent of and prior to the rep flip.

## Memory-cap finding

The native self-host codegen SIGSEGVs under `ulimit -v 2621440` (2.5 GiB) where uncapped it proceeds
to link — i.e. the native self-emit peaks OVER 2.5 GiB. Under the cap the overflow surfaces as a
`tk_region_alloc` fault rather than a clean OOM. Reported per the owner's cap law; not fixed here.

## What N112.1 / N112.2 still buy (landed alongside this note)

Independent of the crash outcome, N112.1 collapses the three "16" width authorities (`fat_slot_bytes`,
`field_layout_size`'s fat case, `error_field_size_of`) into one per-type oracle `fat_value_bytes(t)`
(the raiz-comum R0 debt), and N112.2 routes the fat-image read/write through one path (R2). Both are
INERT (16 for str AND slice) and byte-preserving — they pay down real debt the rep flip (whenever it
lands, for its own reasons) will build on.
