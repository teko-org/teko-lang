## Root cause PINNED (gdb, ASLR-off, deterministic)

The crash is a **use-after-free of the current region**: `tk_alloc → tk_region_current()` returns a
region that has already been `free()`d, and `tk_region_alloc` dereferences its `head` field which
glibc `tcache_put` has overwritten with a mangled pointer (`head = 0x5550037d4f52`, poisoned right
after `free`). Confirmed at the fault: `cur_rsp = 4`, `cur_regions[3] = tk_region_current() =
0x555556282d50` = the freed region.

The dangling `current` is caused by a **`cur_rsp` (current-region stack) LEAK in the native lowering
of an early `return` from inside NESTED LOOPS**. Measured across the crash run:

```
find_cmp_def entry            cur_rsp = 0
is_fused_compare entry        cur_rsp = 4     <- find_cmp_def LEAKED +4
select_fused_branch_x86 entry cur_rsp = 4
```

`backend::find_cmp_def` (`isel_arm64.tks:1368`) is two nested `loop`s with an early
`return match inst.op { … }` from inside BOTH loop bodies. The whole rest of the native backend runs
at `cur_rsp = 0` (frame regions oscillate enter/leave transiently); this one function returns leaving
`cur_rsp = 4` — four `tk_region_enter_u` with no matching `tk_region_leave` on the taken
return-through-nested-loops path. The leaked entries point at frame/loop regions that are then
`tk_region_drop_u`'d (freed) by later emit helpers (`selctx_x86_emit`/`jcc_x86`/`cmp_x86`, whose
frame regions malloc-recycle the very same freed address `0x555556282d50`), so `tk_region_current()`
== a freed region. The next `tk_slice_elem_box` (`select_fused_branch_x86`, boxing its 72-byte
`SelCtxX86` return) bumps from that freed region → SIGSEGV in `tk_region_alloc`.

Family: region-lifetime / enter-leave imbalance (the #5 `push_inst_block` region family), on the
`return`-from-nested-loops facet. Fix target: the native `return`/loop-region unwind in `lower.tks`,
byte-preserving for the C route.

## The fix (`src/lir/lower.tks` only — native lowering; C route untouched)

`lower_return`/`lower_return_fat` ran `emit_region_leaves` (detour `current` to the conveyance anchor
`rr`) but never set `bracket_depth = 1` around the return VALUE — unlike every other exit edge that
detours before lowering a value (`lower_binding_conveyed`, `lower_assign_conveyed`,
`lower_conveyed_tail_expr_stmt`, `lower_match_subject_conveyed`, `lower_conveyed_tail_expr_stmt_fat`,
all of which pair their leave with `ctx_with_bracket_depth(left, 1)`). So a return VALUE that itself
opens lexical regions (`return match … { … }`/`return if … { … }`) ran `open_native_region`
UNSUPPRESSED after the detour — emitting `tk_region_enter_u` with no matching `tk_region_leave`
(`open_native_region`'s own `bracket_depth > 0` skip never fired), leaking `cur_rsp`. The fix wraps
the return-value lowering in `bracket_depth = 1` and restores it after, so the arms' region opens are
no-ops and the value lands at `rr`. `emit_region_drops` (region-stack read only) is unchanged.

Byte-preserving proof: `push_mem_operand_x86`/`encode_frame_addr_x86` (and every non-value-returning
function) are BYTE-IDENTICAL between the pre-fix `gen2` and the fixed `gen2f` (`disassemble` diff);
only functions with a region-opening explicit return change. C-route fixpoint holds:
`gen1bf` builds `gen1cf`, `teko.c` AND the binary byte-identical.
