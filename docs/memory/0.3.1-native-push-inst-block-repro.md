# native/push-inst-block-fix: escaping aggregate element/field write reclaimed under the container (#5)

## Symptom
`lir::push_inst_block` aborts with a spurious M.1 "out of memory (str concat)" (exit 134) — or,
depending on the garbage bytes, a plain SIGSEGV (139) — when a native-built compiler (gen2) native-
builds gen3. The corrupt input is a `b.insts` fat header with a garbage `len`/`ptr` driving
`teko::list::push`. "int-result match" is only the trigger VOLUME (`lower_match_value` hammers the
`alloc_block` + `append_inst` self-append path); the match tag model is not implicated.

## Minimal repro (self-contained, native SIGSEGV; C route exit 42)
`examples/probes/push_inst_block_selfappend/` mirrors `lir::append_inst` → `lir::push_inst_block`:

```
type Blk = struct { id: u32; insts: []i64 }
type Fn  = struct { blocks: []Blk }

fn push_inst_block(b: Blk, inst: i64): Blk {
    Blk { id = b.id; insts = teko::list::push(b.insts, inst) }   // self-append the fat member
}
fn append_inst(f: Fn, block_id: u32, inst: i64): Fn {
    mut blocks = f.blocks
    ... loop ... blocks[i] = push_inst_block(blocks[i], inst) ...   // in-place index-assign
    Fn { blocks = blocks }                                          // `blocks` ESCAPES
}
```

Native (own backend): SIGSEGV / M.1. C route: exit 42. Reproduces from `genfix`(C route) at just
TWO blocks with INTERLEAVED appends (`append_inst(f,0,k); append_inst(f,1,k)` in a loop). A single
block, or non-interleaved fills, do NOT reproduce; the functional rebuild (push into a fresh
`nblocks` instead of the in-place index-assign) does NOT reproduce; splitting the index-assign into
`let nb = push_inst_block(blocks[i], inst); blocks[i] = nb` does NOT reproduce.

## Root cause PINNED (objdump + gdb on the faulting native binary)
gdb: the fault is a `mov (%rax),%rcx` in the READER (`total`) with `rax = 0x7` — a scalar
instruction value stomped into `blocks[k].insts.ptr`. So the STORED `blocks` buffer already held a
corrupt `Blk`. objdump of `append_inst`: `[]Blk` is an array of 8-byte POINTERS to boxed `Blk`s
(aggregate slice elements are held BY ADDRESS). The store is:
```
call teko_narrow__push_inst_block         ; builds+boxes the new Blk, returns its ptr
call tk_slice_elem_box (rsi=0x18)         ; RE-boxes the 24-byte Blk into the CURRENT region
mov  [rbx], rcx                            ; store box ptr into &blocks[i]
call tk_region_leave / tk_region_drop_u    ; <-- drops the region the box was allocated in
```
`tk_slice_elem_box` allocates in `tk_region_current()` (teko_rt.c:4569). In `append_inst` the store
runs inside a per-CALL frame region that `tk_region_drop_u` reclaims on return — so the boxed `Blk`
that `blocks[i]` points at is FREED the moment `append_inst` returns, from under the `blocks`/`f`
the function RETURNS. With interleaving, block-0's freed box and block-1's freed box get
cross-recycled by the next iteration's allocations, and an instruction value (7) lands where a
former box's `insts.ptr` was. A single block's freed-and-reused box happens to be benign; interleaving
makes the reuse malign. Family: #1 region-lifetime (bracket the escaping accumulator to an outliving
region), a NEW site.

## Why the escape bracket never fired
`lower_assign` (lower.tks) runs the NP3b conveyance bracket (`emit_region_leaves` → detour
`tk_region_current()` to the `rr` anchor → dispatch → `emit_region_enters`) iff
`binding_conveys_escape(ctx.escaping, a.name)`. But the checker's `type_index_assign` (and the
field-assign build) leave `a.name` EMPTY and carry the place in `a.target`. So the escape test ran
against `""`, was always false, and an ELEMENT/FIELD write NEVER got bracketed — its per-EXECUTION
box stayed in the reclaimed frame region. The C route holds aggregate elements BY VALUE inline (no
separate box), so its identical `a.name == ""` is harmless and it reads back correctly.

## Fix (lower.tks only — native; C route untouched, byte-preserving)
Derive the escape-test name from the target's ROOT variable for `Field`/`Index` writes
(`assign_escape_target_name` / `texpr_root_var_name`): the escaping thing is the CONTAINER at the
base of the place (`blocks` in `blocks[i] = …`), not the always-empty `a.name`. `Simple`/`RefDeref`
keep using `a.name`. An escaping container now brackets the whole dispatch, so the box materializes
at `rr` and outlives the frame.

## Proof
- Minimal repros all fixed: `push_inst_block_selfappend` 42, `narrow` (2-block interleaved) 42,
  `pshape` (3-block) 96 — all were SIGSEGV/M.1 before.
- C-route fixpoint: gen2c == gen3c BYTE-IDENTICAL (teko.c AND binary) — the change does not perturb
  the C route.
