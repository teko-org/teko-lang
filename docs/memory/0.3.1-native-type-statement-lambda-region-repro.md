## Root cause PINNED (gdb, ASLR-off, deterministic) — type_statement is a VICTIM

`type_statement`'s `match s { … 9 arms … }` compiles to a tag dispatch (`*(i32)s == 0..8`) plus a
defensive **exhaustiveness fallback** at `type_statement+0x1042` (`0x3afd3f`) that does
`mov $0x0 → [rsp+0x3b0]` (a NULL result pointer) and jumps to the shared box trampoline
(`+0xa2`), which `tk_slice_elem_box(elem = NULL, 24)` → memcpy-from-NULL → SIGSEGV.

The fallback fires because the `parser::Statement` `s` passed in has an **invalid tag**: at the
fallback (before the arg slot is reused as scratch) `s = 0x55555a05a460`, `*(i32)s = 0x5a05a450`
(a pointer, not a tag `0..8`). gdb up the frames:

- `type_block` got `stmts.ptr = 0x55555a05a470  stmts.len = 1`; element[0] = `s = 0x55555a05a460`.
- `type_lambda`'s `lam = 0x55555a05a480`: fields read plausibly (`params.len = 2`, `body.len = 1`,
  `body.ptr = 0x55555a05a470`) but **every pointer leads to garbage** — `param0.name.ptr` is junk,
  `param1.name` resolves INTO a raw `.tks` source-text buffer (`src/backend/…emit_native_arm64…`).

So the ENTIRE region `0x55555a05_a4xx` that holds this lambda's AST (its `Lambda`, its
`[]LambdaParam` params, its `[]Statement` body, and the body's `Statement` wrapper) has been
**freed and reused** for later parser allocations (source text). Self-referential 0x10-stride
pointers + a libc address + a `0x7fff00000016` fat-slice header in the wrapper are the tcache/reuse
signature. A wholesale **use-after-free of the parsed-lambda AST region** — NOT a `type_statement`
lowering defect and NOT the `d9a4e19a` bare-payload/null-union family.

Family: **region-lifetime / by-address escaping element** (the `push_inst_block` #5 /
`bracket_to_root` / `select_fused_branch_x86` family). A parsed aggregate (this lambda subtree)
escapes up the AST but lives in a region that is later reclaimed. The C route (`TEKO_BACKEND=c`)
checks the same statement fine; only the native-built compiler faults.

## Trigger LOCALIZED (gen2-as-probe, no rebuild) — `parse_lambda`'s bare-expr body

The crashing lambda is `(enc, dwarf) => teko::backend::emit_macho(enc, dwarf)` (`project.tks:3557`;
its twin `emit_elf_arm64` at `:3581`) — item 1827 = `fn emit_native_arm64`. The corrupt `param1.name`
resolved INTO `project.tks`'s own source text at exactly that region, and items 1822-1825 warned on
`project.tks`.

`parse_lambda` (`parse_expr.tks:286`) builds a bare-expression body (no `{}`) via
`body = teko::list::push(teko::list::empty(), ExprStmt { expr = e.node })` (line 320) inside the
`else` arm; the `{}`-block path (line 316) sets `body = blk.items` from `parse_block`'s return.
Rewriting the two `project.tks` lambdas to block bodies `(enc, dwarf) => { … }` and re-running the
UNCHANGED gen2 self-build advances it from item 1827 to **item 4940/7080** (same `type_statement+0xd7`
box crash at the NEXT bare-expr lambda). So the bare-expression body path is the trigger: the pushed
`ExprStmt` wrapper (widened to `Statement`, `tk_slice_elem_box`, 24 B) is boxed into a region
reclaimed when `parse_lambda` returns, while the escaping `body` slice ptr-array survives — a
per-EXECUTION element boxed under a region shorter-lived than the container it escapes into. The
block path is immune because `parse_block` RETURNS its `[]Statement`, and the return-value
conveyance (`own_returned_value` → `box_aggregate_value` at `rr`, with `emit_region_leaves`
detouring runtime-current down to the anchor) boxes the elements into an outliving region.

## THE FIX (`src/parser/parse_expr.tks` only — C route byte-identical)

`parse_lambda`'s bare-expression body was built inline in the `else` arm:
`body = teko::list::push(teko::list::empty(), ExprStmt { expr = e.node })`. Extracted into a new
`lambda_expr_body(e: Expr): []Statement` whose tail `push` IS its return value, and the `else` arm
now assigns `body = lambda_expr_body(e.node)`. The return-value conveyance (`own_returned_value` →
`box_aggregate_value` at the root anchor `rr`, with `emit_region_leaves` detouring runtime-current)
now parks the `ExprStmt` element box in an outliving region — exactly what the `{ … }`-block path
already got from `parse_block`'s return. An escaping ASSIGN inside an if-arm did not park that
by-address element box; a RETURN does. Pure refactor; the C emitter lowers it identically.
