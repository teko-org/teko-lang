# native/func-type-fix: reproduced native miscompile of func_type's `Type | error` return

## Symptom (gen2 native-built, aborts native-building gen3)
The checker fails at item 0 emitting ~25 diagnostics, EACH with an EMPTY message and a
garbage position `1439897514:21845` (col `21845` = `0x5555`, the top bytes of a PIE/heap
pointer under `setarch -R`):
```
  checker    0/7075 items   2.4s  ✗  src/build/project.tks:1439897514:21845:
teko: .: src/build/project.tks:1439897514:21845:
src/checker/escape.tks:1439897514:21845:
src/checker/typer.tks:1439897514:21845:
src/codegen/codegen.tks:1439897514:21845:
...
```
The pinned M.1 "out of memory (str concat)" (exit 134) is the SAME defect with a huge
garbage message length; this run's payload bytes gave an empty/short length, so it fell
through to exit 1 instead of the malloc abort. Same by-address corruption either way.

## The path
`collect_fn_signature(item, f, table, env)` (src/checker/collect.tks:303):
```
match func_type(f, table, item.namespace) {
    Type as t => ...define_fn...
    error as e => SigOutcome { ...; diags = one_diag(located_diag(item.file, f.line, f.col, e)) }
}
```
The `file` field of each diagnostic is CORRECT (it is `item.file`, collect's own arg, not
from the error). But `located_diag` (diagnostics.tks:37) takes line/col/message FROM the
error `e`:
```
let line = if inner.line != 0 { inner.line } else { decl_line }   // inner.line = 1439897514 (garbage, nonzero)
let col  = if inner.line != 0 { inner.col }  else { decl_col }     // inner.col  = 21845 = 0x5555
diag_at(file, line, col, inner.message)                            // inner.message = garbage str
```
So `func_type` returns a value whose union tag reads as `error` and whose payload
(line/col/message) is garbage — a by-address corruption of the `Type | error` return.
The C route accepts the same source, so this is NOT a legitimate signature failure.

## STATUS: reproduced; root-cause instrumentation next.
Candidate: `func_type` (collect.tks:80) builds `params: []Type` / `param_names: []str` /
`defaults: []parser::Expr` by self-append push inside a loop, then returns
`Func { params; ret; ...; param_names; n_required; defaults }` as `Type | error`. The
`Type | error` aggregate union return is read by-address at the `collect_fn_signature`
match; a slice member conveyed through a reclaimed region would corrupt the union tag/payload.
Same family as 5026006a (region-lifetime) / 74622f77 (free-old) — to be pinned by
instrumenting the actual faulting value before the fix.

## ROOT CAUSE PINNED (native match-arm variant-construct tag = ARM POSITION, not member index)
Instrumentation proved the failing functions ALL have a `ref T` param; `func_type` calls
`resolve_type` which for `ref T` reaches `ref_target_type` (resolve.tks:2424):
```
match argt {
    Reference => error {...}   // arm 0
    Ptr => error {...}          // arm 1
    Uptr => error {...}         // arm 2
    Func => error {...}         // arm 3
    _ => Reference { inner = argt }   // arm 4  (Reference is a member of Type -> tag Type=0 in Type|error)
}
```
A `REFRES` probe right after `ref_target_type` reads the union as `error`, not `Reference`.

Minimal repro (compiled by genB native, /scratchpad/mini): a variant member built DIRECTLY
as a MATCH-ARM tail gets the WRONG tag. Disassembly of `match a { 0 => Other{y}; _ => Inner{x} }`
(`Thing = variant Inner | Other`) shows:
  - arm 0 (`Other`, member index 1) stores tag = 0
  - arm 1 (`Inner`, member index 0) stores tag = 1
i.e. TAG = ARM POSITION, not the member's variant index. Confirmed on a 3-arm variant
(`desc`: arms store 0,1,2 regardless of member index) and that the PAYLOAD is the taken
arm's (correct) — only the TAG is wrong. `if`-arms (P3) and non-match tails (B) and same-tag
arms (q1/q2) are CORRECT; the bug is MATCH-arm-specific and only visible when a member's
index != its arm's position.

`ref_target_type` is a perfect instance: the success `_` arm (Reference -> Type, tag 0) sits
at position 4 after four `error` (tag 1) arms, so it stores a position-4 tag; the reader's
`Type as t / error as e` match then misreads it -> spurious `error` with garbage payload ->
the empty-message / M.1 abort. C route (codegen.tks) computes the tag correctly; only the
native backend (lower.tks path) is wrong. NEXT: locate the exact tag-index computation that
uses arm position.

## FIX (native arm-join variant-tag widen — lower.tks only, C route untouched)
`lower_value_into_type`'s variant arm now calls `arm_join_retag_into`: when the value is an
`if`/`match` whose inferred variant type is NOT the target's tag layout but every member reaches
the target, it retags the node type to the declared `bound` and re-lowers via `lower_expr`, so
each arm's tail coerces DIRECTLY into the declared variant's tag space (re-wrapping a nested
sub-member like `Reference`->`Type` correctly). Mirrors codegen.tks:6771 (the C route's emit_as
re-tag). Helpers `variant_tag_layout_matches` (skip when tags already align — byte-identical) and
`variant_all_members_reach` (mirror `cg_narrow_variant_widens_into`).

## PROOF
- Minimal repro (scratchpad/mini, genfix native): every reordered/nested case now CORRECT
  (p2 Inner x=7, desc A3 a=7, if-reversed Inner x=7, `Thing | error` error-arm-first nested case).
- Self-host: genfix(C, fixed): gen2fix(native): gen2fix builds gen3fix: the func_type
  ~25 empty-message / `0x5555` garbage diagnostics are GONE; the build now advances PAST the
